# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the three net-new UI surfaces named in the phase brief —
(1) `WeekWizard.tsx` guided-fill accordion, (2) New Plan dialog's `start_date` + `people_multiplier`
additions, (3) plan list/header date display + Outputs-page multiplier badge. Interaction
mechanics (accordion-not-modal, tap-to-toggle Chips, staples pre-fill, LRU order) are LOCKED by
`04-CONTEXT.md` D-01..D-04 and are **not** re-specified here — this file only fixes the visual
layer on top of those locked mechanics, consistent with the existing MUI 7 theme already live in
`recipe-planner/src/`. The template-editor UI is explicitly out of scope (D-01 defers it) — no
screens are specified for template/slot CRUD.

## Spacing Scale

MUI's `sx` spacing shorthand already resolves to multiples of 8px (`theme.spacing(1) = 8px`), confirmed against existing usage (`p: 2` = 16px, `gap: 1` = 8px, `mb: 2` = 16px throughout `WeeklyPlans.tsx`). Use the same `sx` spacing units for all new Phase 4 UI — do not introduce raw pixel values except the one named touch-target exception below.

| Token | Value | `sx` unit | Usage |
|-------|-------|-----------|-------|
| xs | 4px | `0.5` | Chip internal icon gaps, badge padding |
| sm | 8px | `1` | Gap between wizard Chips, gap between Accordion sections |
| md | 16px | `2` | Accordion panel internal padding, dialog field spacing (matches existing `Paper sx={{ p: 2 }}` idiom) |
| lg | 24px | `3` | Space between wizard's Staples section and the rest of the accordion |
| xl | 32px | `4` | (available; no mandated use this phase) |
| 2xl | 48px | `6` | (available; no mandated use this phase) |
| 3xl | 64px | `8` | (available; no mandated use this phase) |

**Exceptions:**
- **44×44px minimum touch target** on every tappable element net-new to this phase (wizard pick Chips, "Confirm Staples" button, Accordion summary rows, off-pool Autocomplete's input row). This is a tablet-first hard floor per `04-CONTEXT.md` ("Tablet touch targets") and is **not** a multiple of 8 — treat it as an explicit `minHeight: 44` override, not a spacing-scale token. MUI's default small `Chip` (24px) and default `Button` (36px) are both under this floor and must be overridden (see Typography section, Chip spec below).

## Typography

All values are MUI 7 stock `Typography` variant defaults (verified, no `theme.typography` override exists) — declared here, not newly introduced, so executor code should use the named `variant` prop rather than hand-rolled `fontSize`/`fontWeight` sx overrides wherever possible.

| Role | Size | Weight | Line Height | MUI variant |
|------|------|--------|-------------|--------------|
| Body | 16px | 400 (regular) | 1.5 | `body1` — wizard field labels, dialog TextField values, multiplier helper text |
| Label | 14px | 400 (regular) | 1.43 | `body2` / `subtitle2` — Chip pick labels at default size, "N of {count} picked" badge text, plan-list secondary date line |
| Heading | 20px | 500 (medium — MUI `h6` stock weight, not a new token) | 1.6 | `h6` — Accordion section titles ("Staples", "Dinner"), dialog titles, Outputs page section headers |
| Emphasis | 14–16px | 700 (bold) | inherits | `sx={{ fontWeight: "bold" }}` applied to `body1`/`subtitle2` — reused exactly as the existing `tagName` label at `WeeklyPlans.tsx:749` and table headers at `WeeklyPlans.tsx:841/848`; use for the fully-picked badge state and the "Confirm Staples" button label only |

**Declared set: 4 sizes (14/16/20 + the existing bold-emphasis treatment at 14-16), 2 weights (400 regular, 700 bold/emphasis).** Do not introduce 500-weight `semibold` as a new hand-set token — the one place 500 appears (`h6`) is MUI's own stock default, left as-is, not a token this phase controls.

**Wizard Chip exception (tablet legibility):** the default MUI `Chip` label font-size (13px) is below this contract's 14px floor. All wizard pick Chips must set `sx={{ fontSize: "0.875rem" /* 14px */, height: 40, px: 1.5 }}` — see Chip state spec below. This is the one place a Chip deviates from its default MUI sizing, and it is intentional (touch/legibility, not a new arbitrary size).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (MUI light `background.default`/`background.paper`, unset/stock) | Page background, `Dialog` background, `Accordion`/`AccordionDetails` background, main content area |
| Secondary (30%) | `#fafafa` (MUI `action.hover` / stock light Paper elevation tint) | Drawer nav, collapsed `AccordionSummary` resting background, `TableContainer` header row, disabled/incomplete slot panels |
| Accent (10%) | `#2e7d32` (theme `primary.main`, existing) | RESERVED FOR: "Fill Week" CTA (`WeeklyPlans.tsx` plan header), "Confirm Staples" button, `AppBar` background (pre-existing, unchanged), expanded `AccordionSummary` indicator/border-left, the completion checkmark icon shown once a slot's picks reach its target count. **Not** for pick-`Chip` fills (those keep the pre-existing per-tag `SLOT_COLORS`/tag-color idiom — see below) and **not** for the "N of {count}" badge in its default state (see Copywriting/Interaction States — mirrors the Phase 2 precedent of never using `success.main`, which is byte-identical to this accent green, to avoid diluting the 10% budget). |
| Destructive | `#d32f2f` (MUI stock `error.main`) | Reserved for destructive actions only. No **new** destructive action is introduced by this phase (see Copywriting Contract) — this row exists only to confirm the existing `color="error"` idiom (`WeeklyPlans.tsx:1099`, delete-meal confirm dialog) is unchanged and must not be reused for anything non-destructive in the new wizard. |

**Second semantic color — multiplier state indicator:** `#ff6f00` (theme `secondary.main`, already defined but under-used in the current codebase). Reserved exclusively for the **people-multiplier badge** on the Outputs page and the plan list/header, and **only rendered when `people_multiplier !== 1`**. At the default multiplier of 1, render nothing — no badge, no color, no chip — so a normal (unscaled) week looks pixel-identical to today's output, matching WEEK-02's "multiplier of 1 reproduces today's output exactly" requirement extended to the visual layer, not just the data layer.

**Existing per-tag/per-slot color idiom (not part of the 60/30/10 budget, explicitly preserved):** `SLOT_COLORS` (`src/constants/mealPlanning.ts`) and each `tags` record's own `color` field already drive Chip backgrounds throughout `WeeklyPlans.tsx` (`:743-778`, `:817-830`, `:860-867`). Wizard pick Chips and Accordion slot-title Chips reuse these exact colors unchanged — they are data-driven, not theme-driven, and sit outside this contract's accent budget by long-standing project convention.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (launch wizard) | **"Fill Week"** — button on the `WeeklyPlans.tsx` plan header, positioned beside the existing "Add Meal" button; icon `AutoAwesome` or `PlaylistAddCheck` from `@mui/icons-material`, `variant="contained"`, accent green |
| Staples fast-path CTA | **"Confirm Staples"** — the one prominent action in the pre-expanded Staples accordion panel; advances to the next slot without individually re-tapping already-toggled chips |
| Off-pool add affordance | **"+ Add other recipe"** — label on the docked `Autocomplete` at the bottom of each expanded slot panel (reuses `WeeklyPlans.tsx:998-1018`'s exact Autocomplete, new label text only) |
| Skip/advance affordance | **"Skip this slot"** (0 picks) / **"Next slot"** (partial picks, count not yet reached) — small text `Button` pinned bottom-right of each expanded panel, always available (a slot is never blocking per D-02) |
| Empty state — no template seeded | Heading: **"No week template yet."** Body: **"The household week template hasn't been set up on this database yet. Run the seed script, then reopen this wizard."** (Surfaces the D-01 seed-once model's failure mode explicitly rather than showing a blank/broken accordion.) |
| Empty state — slot pool has zero eligible recipes | Heading: **"No recipes tagged for this slot yet."** Body: **"Tag a recipe with '{tag name}' in the recipe editor, or add one directly below."** (Points at the exact fix — tagging — and at the always-available off-pool Autocomplete as the immediate workaround.) |
| Error state — wizard pick write fails | **"That pick didn't save. Check your connection and try again."** — inline `Alert severity="error"` under the affected slot's Chip row (the wizard's `create()` call is a direct, non-optimistic write per RESEARCH.md Pattern 6 — unlike the Phase 2 shopping-state hook, there is no automatic retry queue here, so the error must be visible and the Chip must revert to un-toggled on failure) |
| Multiplier field label | **"People multiplier"** with helper text: **"Scales shopping, prep, containers, and pull lists (e.g. 1.5 for a guest week). Leave at 1 for normal."** |
| Multiplier badge (Outputs page + plan header, shown only when ≠ 1) | **"×{value} servings"** e.g. `"×1.5 servings"` — secondary-orange `Chip`, `size="small"` |
| Start-date field label | **"Week starting (Monday)"** — native `<input type="date">` via `TextField type="date"`, defaulted to the upcoming Monday |
| Plan list / header date display | **"Week of {Mon D, YYYY}"** e.g. `"Week of Jul 6, 2026"` — reuses the exact phrasing already hard-coded as the plan-name placeholder at `WeeklyPlans.tsx:969` ("e.g., Week of Jan 6"), now rendered as real derived text from `start_date`, not user-typed |
| Destructive confirmation | **None introduced this phase.** Untoggling a wizard pick Chip before the slot is confirmed is a plain toggle (no confirmation dialog — matches D-02's "individual chips stay toggleable to drop/add before confirming"). The pre-existing delete-meal confirmation flow elsewhere in `WeeklyPlans.tsx` is unchanged and out of scope. |

## Phase 4 Interaction States

Supplementary to the sections above — the concrete visual states the executor must implement for each net-new surface, since D-02's interaction *mechanics* are locked but the *states* were not yet visually specified.

### Accordion (`WeekWizard.tsx`)

| State | Visual |
|-------|--------|
| Expanded (active slot) | `AccordionSummary` background `#ffffff`; 4px accent-green (`#2e7d32`) left border on the `Accordion` root (`sx={{ borderLeft: 4, borderColor: "primary.main" }}`) to mark "you are here"; title in `h6`/20px/500 |
| Collapsed, 0 or partial picks | `AccordionSummary` background `#fafafa` (secondary/30% surface); title in `body1`/16px/400; "N of {count} picked" badge — `Chip size="small" variant="outlined"` (grey, not accent) |
| Collapsed, fully picked (N === target count) | Same as above, plus a small `CheckCircle` icon in accent green (`#2e7d32`, 16px) immediately left of the badge — the **only** accent-green touch in the collapsed state; the badge `Chip` itself stays outlined/grey (do not fill it green — mirrors the Phase 2 "don't overload the accent budget" precedent) |
| Staples slot specifically | Always accordion position #1, always **pre-expanded** on wizard open regardless of scroll/auto-advance state elsewhere; last week's picks arrive pre-toggled (filled Chips) before any user interaction |

### Wizard pick Chip (recipe selection)

| State | Visual |
|-------|--------|
| Unselected (not picked) | `variant="outlined"`, border in the recipe's tag color (or `SLOT_COLORS[slot.meal_slot]` if untagged), text `text.primary`, `sx={{ fontSize: "0.875rem", height: 40, px: 1.5 }}` (14px text, 44px-plus-padding hit target) |
| Selected (picked) | `variant="filled"`, `backgroundColor` = tag color / `SLOT_COLORS[slot.meal_slot]`, `color: "white"` — identical idiom to `WeeklyPlans.tsx:755-772`, just `onClick` toggle instead of `onDelete` |
| Disabled (should not occur — a slot is never blocking, so no chip is ever disabled; if a recipe is already picked elsewhere this phase does not cross-slot-dedupe) | not applicable this phase |

### "N of {count} picked" badge

`Chip size="small" variant="outlined" label="{n} of {count} picked"` — 12-14px caption/label text, grey border/text (`color: "text.secondary"`), never accent-filled (see Accordion table above for the one permitted accent touch — the adjacent checkmark icon, not the badge itself).

### New Plan dialog additions (`WeeklyPlans.tsx` plan dialog, `:953-987`)

- `start_date`: `TextField type="date" label="Week starting (Monday)"`, placed directly below the existing "Plan Name" field, same `margin="dense" fullWidth` treatment. Default value = the upcoming Monday (client-computed, not server-defaulted). No calendar-widget picker (confirmed `@mui/x-date-pickers` not installed — RESEARCH.md).
- `people_multiplier`: `TextField type="number" label="People multiplier"` with `inputProps={{ step: 0.5, min: 0.1 }}`, default value `1`, same field-row treatment as `start_date`. Helper text per Copywriting Contract above. Client-side guard: reject/clamp values `<= 0`.

### Plan list + header (`WeeklyPlans.tsx`, `:584-587` list, `:792-794` header)

- Plan list `ListItemText` secondary line gains the formatted `start_date` string (see Copywriting Contract) alongside/after the existing plan name.
- Plan header (`:792-794`, currently just `{selectedPlan.name || "Unnamed Plan"}`) gains the same formatted date as a `Typography variant="body2" color="text.secondary"` line directly beneath the plan-name `h6`.

### Outputs page multiplier badge

Rendered adjacent to the plan selector on `Outputs.tsx`, **only when `selectedPlan.people_multiplier !== 1`** (see Color section). `Chip size="small" label="×{value} servings" sx={{ backgroundColor: "secondary.main", color: "white" }}`. At multiplier `1`, this Chip does not render at all — no placeholder, no empty space reserved.
