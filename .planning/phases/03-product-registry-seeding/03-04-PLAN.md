  <behavior>
    - resolveSeedRow(row, existingRawByName): an EXACT case-insensitive name match with empty fdc_id returns action "BACKFILL" carrying the fdc_id/usda_* to write; an exact match that already has fdc_id returns "SKIP" (no-op).
    - A conservative fuzzy near-match (below the tight review threshold, e.g. fuse score < 0.2) returns "SKIP_REVIEW" — never "INSERT" or "MERGE".
    - A genuine miss (no exact, no near-match) returns "INSERT".
    - A same-name product of a DIFFERENT type (e.g. an existing stored "chicken stock" vs a new raw "chicken stock") does NOT block the raw insert — it is recorded as a cross-type collision review flag, and the raw INSERT still proceeds.
  </behavior>

Critical scoping (Pitfall 2, verified against pb_schema.json): the hard-dedup query filters `type = "raw"` (121 records) — the unique index is composite `(name COLLATE NOCASE, type)`, so a cross-type same-name product must NOT be treated as a hard duplicate; instead quarantine cross-type name collisions into a separate review section (mirror find-duplicates.js's crossTypeCollisions), never a hard block. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dev-machine seed script → prod PocketBase | Superuser-authenticated bulk writes to the live single-household registry |
| offline usda-seed.json → seed script | Locally-built seed rows inserted as products |
| local `.env.local` → script | PocketBase superuser credentials at runtime |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-07 | Tampering | seed-usda.js bulk product writes to prod | high | mitigate | Mandatory `--dry-run` report reviewed by human BEFORE any write; test `:8091` rehearsal first; `pb.backups.create()` backup-before-mutate on the prod path (Phase-1 precedent); idempotent resolver so a re-run backfills/skips rather than duplicating; blocking human-verify checkpoint |
| T-03-08 | Tampering | False auto-merge on a fuzzy near-match corrupting an existing product | high | mitigate | D-03 conservative posture — near-match is SKIP_REVIEW only, NEVER auto-merge; tight hard-dedup threshold (~0.2) distinct from the search threshold; unit-tested resolver behavior |
| T-03-09 | Denial of Service | Insert rejected by the composite unique index producing a confusing runtime error | medium | mitigate | Hard-dedup scoped to `type="raw"` matching the actual `(name COLLATE NOCASE, type)` index; genuine-miss inserts cannot collide because exact same-name raw rows are caught first |
| T-03-02 | Information Disclosure | PB superuser credentials | medium | mitigate | Reuse gitignored `.env.local`; never print/commit |
</threat_model>
