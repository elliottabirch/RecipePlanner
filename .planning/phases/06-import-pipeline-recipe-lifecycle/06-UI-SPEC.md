# Phase 6 — UI Design Contract

> Visual and interaction contract for the Import Pipeline & Recipe Lifecycle phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This is an EXISTING React + MUI (Material UI v7) + ReactFlow app. This phase adds MODEST new surfaces onto the established design system — it is NOT a greenfield design. Every token below is the app's current MUI theme/pattern, extracted from source, not invented. shadcn is intentionally **not** adopted (would fork the design system mid-project). All new UI reuses MUI components + existing patterns and is tablet-first per project decisions.

## Spacing Scale

The app uses MUI's default 8px spacing unit; `sx` props take multipliers (`gap={1}` = 8px, `p={4}` = 32px, `mb={0.5}` = 4px). Declared values in active use (all multiples of 4):

| Token | Value | MUI multiplier | Usage in this phase |
|-------|-------|----------------|---------------------|
| xs | 4px | 0.5 | Icon-to-label gap in card header (draft badge next to title), inline chip gaps |
| sm | 8px | 1 | Compact stack spacing, `Grid` gap, chip-row `gap` |
| md | 16px | 2 | Default `Grid container spacing={2}` between recipe cards; form-field vertical rhythm |
| lg | 24px | 3 | Dialog content section padding |
| xl | 32px | 4 | Empty-state `Paper` padding (`p: 4`), page action-bar breathing room |

Exceptions:
- **Touch targets (tablet-first):** one-tap note buttons and the publish action use MUI `IconButton`/`Button size="medium"` which render ≥40px hit area; ensure ≥44px effective touch target on the three note-attach surfaces (recipe card, cook-mode Now/Next card, calendar cell). This is the only intentional deviation and it is a minimum-size floor, not a new spacing token.

## Typography

MUI default Roboto type scale — the roles actually used by this phase's surfaces (do not introduce new sizes/weights):

| Role | MUI variant | Size | Weight | Line Height |
|------|-------------|------|--------|-------------|
| Card title / dialog title | `h6` | 20px (1.25rem) | 500 (medium) | 1.6 |
| Body (recipe notes, dialog copy, parse feedback) | `body1` | 16px (1rem) | 400 (regular) | 1.5 |
| Secondary / caption (empty-state text, meta) | `body2` | 14px (0.875rem) | 400 (regular) | 1.43 |
| Chip / badge label | (Chip) | 0.7rem (~11px) | 600 (semibold) | n/a (chip) |

Weights in use: **400 (regular)** for all body copy and **500/600 (medium/semibold)** for titles and chip labels — matches the existing Batch chip (`fontWeight: 600`, `fontSize: "0.7rem"`) and card `h6` title. No new weight is introduced.

## Color

Theme palette (`src/App.tsx`): `primary.main = #2e7d32` (green), `secondary.main = #ff6f00` (orange), MUI light mode.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` / `#fafafa` | Page background + `CssBaseline` surfaces |
| Secondary (30%) | `#ffffff` Paper/Card + drawer nav | Recipe cards, dialogs, left nav drawer |
| Accent (10%) | `#2e7d32` (primary green) | **Primary actions only:** the Publish button (`variant="contained"`), the import page's "Import recipe" primary button, the queue `Badge` in nav. Never applied to draft badges, category chips, or passive UI. |
| Destructive | `#d32f2f` (MUI `error.main`) | Publish-blocked lint `Alert severity="error"`; note-dismiss / discard-draft confirm buttons (`color="error"`) |

Accent reserved for: the **Publish** button, the **Import recipe** primary button, the nav **queue Badge**. Not for draft badges, tag chips, or note buttons.

**New status color — Draft badge:** `#757575` (MUI `grey.600`), white text — a deliberately muted/neutral chip that reads as "not live / unpublished", visually distinct from the vivid category chips already on the card (Batch `#9c27b0` purple, Tags `#2196f3` blue). Grey keeps the draft state out of the 10% accent budget (a draft is a *state*, not an action). The Draft chip mirrors the Batch chip's exact structure: `size="small"`, `fontWeight: 600`, `fontSize: "0.7rem"`, `height: 22`, `color: "white"`, `backgroundColor: "#757575"`, `label="Draft"`.

Semantic feedback colors (existing MUI `Alert` severities, reused unchanged): `warning` (import validation problems — non-blocking), `error` (publish lint failures — blocking), `info`/`success` (parse-OK feedback).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — import page | **"Import recipe"** (lands the draft, then redirects into RecipeEditor) |
| Primary CTA — publish gate | **"Publish"** (button inside RecipeEditor; flips `status` to `published` only on clean lint) |
| Secondary CTA — note attach | **"Add note"** (one-tap `IconButton` with `NoteAddIcon` + tooltip on the three surfaces) |
| Import page empty state | Heading: *"Import a recipe"* — Body: *"Paste structured recipe JSON below, then Import. It lands as a draft you can review and edit before publishing."* |
| Import parse-OK feedback | `Alert severity="success"`: *"Recipe parsed — {N} ingredients, {M} steps. {K} products need matching before import."* (K omitted when 0) |
| Import validation error (non-blocking) | `Alert severity="warning"`: *"Couldn't read part of this JSON. Fix the items below and Import again — nothing is saved until you do."* Each problem listed as its own line (missing name/unit, unknown step type, edge pointing at a missing node). **Importing never blocks on these until they're resolved; the button stays enabled to re-attempt after edits.** |
| Inline unmatched-product step | Heading: *"Match these products"* — Body: *"{N} ingredients aren't in your registry yet. Pick an existing product, quick-create one, or search USDA — so every line has a store, section, and unit."* Reuses `QuickCreateProductDialog`. |
| Publish blocked (lint findings) | Dialog title: *"Fix {N} issue(s) before publishing"* — each finding an `Alert severity={finding.severity}`: *"**{rule}**: {message}"* (mirrors `Products.tsx:522-556` findings dialog). Dialog `DialogActions`: **"Close"**. Status is never written on failure. |
| Publish success | Draft chip disappears from the card; no modal — the state change is the feedback (recipe now appears in planning). |
| Wizard revision flag | Chip/inline flag on the recipe row: *"Revised — review?"* (present when a pending draft revision links to this recipe via `revision_of`). Tapping opens the draft in RecipeEditor. |
| Empty note surfaces | No empty state — the "Add note" button is always available; after tap, a small `TextField` + "Save note" inline (or compact dialog on the cook-mode card). |
| Destructive — dismiss note | Confirm copy: *"Dismiss this note? It won't produce a revision."* — confirm button `color="error"`, label **"Dismiss"**. |
| Destructive — discard draft revision | Confirm copy: *"Discard this draft revision? The published recipe stays as-is."* — confirm button `color="error"`, label **"Discard"**. |

Tone: terse, reassuring about the never-blocks / recipe-stays-live invariants (matches the two first-class invariants in CONTEXT §Specific Ideas). Every error tells the user nothing was lost.

## Component & Interaction Inventory

New/changed surfaces this phase (prescriptive — executor implements from this; grounded in the cited source files):

### 1. Import page — new route `/import`
- **Route:** add `<Route path="import" element={<ImportRecipe />} />` in `App.tsx` alongside `recipes/*` (App.tsx:53-56).
- **Nav:** add `renderNav("Import", "/import", <ImportIcon />, mini)` in `Layout.tsx` main list (after "Step Backfill", before Registries) — same `renderNav` helper, mini-rail tooltip included. Icon: `FileUploadIcon` or `PostAddIcon`.
- **Layout:** page container matching other pages (`Box` + page title `h6`); a full-width multiline `TextField` (monospace, `minRows={10}`) for JSON paste; primary **"Import recipe"** `Button variant="contained"` (green accent); parse-feedback `Alert` stack above/below the button.
- **Flow:** paste → live/on-submit `validateImportJson()` feedback (`Alert`) → if unmatched products, inline **"Match these products"** step reusing `QuickCreateProductDialog` (+ Search-USDA tab) → on resolve, land draft via shared `buildRecipeGraph({status:"draft"})` → `navigate('/recipes/:id')` into RecipeEditor.
- **Invariant:** the Import button never hard-blocks; validation surfaces problems, resolve step is part of import, not a gate.

### 2. Draft badge — `Recipes.tsx` card grid
- Add a Draft `<Chip>` next to the title in the card header `Box` (Recipes.tsx:414-431), mirroring the Batch chip exactly but grey (`#757575`, `label="Draft"`). Rendered when `item.status === "draft"`. A recipe can show both Draft + Batch chips (draft state is orthogonal to recipe_type) — they sit in the same flex row with `gap={1}`.

### 3. Publish button + lint-gate dialog — `RecipeEditor.tsx`
- Add a **"Publish"** `Button variant="contained"` in the editor action bar, shown only when the loaded recipe's `status === "draft"`.
- On click: call `runRecipeLint(id)`; if findings, open a lint-findings `Dialog` copied from `Products.tsx:522-559` (title *"Fix N issue(s) before publishing"*, one `Alert` per finding, "Close" action) and do NOT write status. If clean, `update(recipes, id, {status:"published"})`; the Publish button then hides.

### 4. One-tap note button — three surfaces
- **Recipe card (`Recipes.tsx`):** small `IconButton` (`NoteAddIcon`) in the card, `source_surface="recipe_card"`.
- **Cook-mode Now/Next card (`components/cook-mode/NowNextCard.tsx`):** `IconButton` in the card header row (near the expand toggle / `ReadinessChip` at NowNextCard.tsx:103-117), thumb-reachable, `source_surface="cook_mode"`.
- **Calendar/week cell (`WeeklyPlans.tsx`):** `IconButton` on the planned-meal cell, `source_surface="calendar"`.
- Tap opens a compact note-entry affordance (`TextField` + "Save note"); writes to `recipe_notes` via `useRecipeNotes` with `status="pending"`. Minimal, ≥44px touch target (tablet). No page navigation.

### 5. "Review revised recipe?" flag — `WeekWizard.tsx`
- When a pool recipe has a linked pending draft revision (a recipe with `revision_of = R.id && status="draft"`), render an inline flag chip *"Revised — review?"* on that recipe's wizard row; tap → open the draft in RecipeEditor. Treatment is Claude's discretion per CONTEXT §Claude's Discretion; keep it a low-emphasis chip (not accent green — use MUI `warning`/`info` outlined chip so it signals "attention" without competing with the primary CTA).
