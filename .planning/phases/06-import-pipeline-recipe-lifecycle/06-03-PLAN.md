<objective>
Build the two pure gate primitives: a fail-open draft-exclusion filter builder (D-04, IMP-01) and `runRecipeLint(recipeId)` composing the existing per-step + per-product linters while deliberately excluding the week-scoped pull-step rule (D-06, IMP-07). Both are testable `src/lib/*` modules; the UI plans (05 draft wiring, 06 publish button) wire into them.

Purpose: the filter string is the single correctness-critical guard against a draft leaking into a meal plan; `runRecipeLint` is the publish gate's rule engine. Getting the fail-open semantics right here (excludes draft, keeps unset) prevents recipes silently vanishing from planning (Pitfall 1).
Output: `draft-filter.ts`, `recipe-lint.ts`, and their tests.
</objective>
